# 航线管理接口

接口基于《场地与航线管理规则》，使用现有 `request` 和 Mock 自动注册机制。

## 接口清单

完整前缀为 `/api/system-management/airlines`。API 封装位于 `src/api/airlineManagement.ts`，调用时不用再添加 `/api`。

| 方法 | 相对路径 | API 方法 | 成功响应 data |
| --- | --- | --- | --- |
| GET | 空路径 | `getAirlineList(params?, signal?)` | `{ list, total }` |
| GET | `/:id` | `getAirlineDetail(id, signal?)` | 完整航线 |
| POST | 空路径 | `createAirline(values)` | 创建后的完整航线 |
| PUT | `/:id` | `updateAirline(id, values)` | 更新后的完整航线 |
| DELETE | `/:id` | `deleteAirline(id)` | `true` |

原始响应统一为 `{ code, message, data }`，API 封装返回解包后的 `data`。成功码为 `0`；参数错误为 `40003`；航线不存在为 `40403`。失败时 `data` 为 `null`，`message` 说明字段或航点序号。沿用现有 Mock 的业务错误约定，不通过 HTTP 状态区分这些业务失败。

## 列表

查询参数：`name?: string`、`page?: number`、`pageSize?: number`。名称去首尾空格后忽略大小写模糊匹配；分页默认 `1 / 10`，页码必须为正整数，单页数量为 `1～100`。非法参数返回校验错误，超出末页返回空数组及正确总数。

按更新时间倒序、编号升序排序，先过滤再分页。每条摘要包含：

```text
{ id, name, waypointCount, length, speed, updatedAt }
```

列表不包含航点和备注。查看、编辑通过详情接口获取完整数据。

## 保存与详情

新增和更新共用请求结构，PUT 整体替换可编辑字段和航点数组：

```json
{
  "name": "滨江巡检航线",
  "speed": 5,
  "remark": "沿江巡检",
  "waypoints": [
    { "longitude": 120.2102, "latitude": 30.2074, "altitude": 0 },
    { "longitude": 120.2152, "latitude": 30.2094, "altitude": 80 }
  ]
}
```

- `name` 去首尾空格后不能为空；允许同名。
- `speed` 为有限数值且大于 0，单位米/秒。
- `remark` 可省略，省略时保存为空字符串；传入时必须是字符串。
- 航点至少两个，经纬度使用 WGS84 度数，范围分别为 `[-180, 180]`、`[-90, 90]`。
- `altitude` 为有限数值且大于等于 0，单位米，相对本次起飞点计算。
- 相邻航点不能同时具有完全相同的经度、纬度、高度；允许垂直升降、路径交叉、非相邻重复点和手动闭合。

详情在列表摘要基础上增加 `remark`、`createdAt`、`waypoints`。每个航点包含请求字段及从 1 开始的 `order`。数组顺序即飞行顺序，服务端重新生成序号。

`id` 使用系统生成的 UUID，样例编号为 `airline-001` 等。时间采用北京时间 `YYYY-MM-DD HH:mm:ss`。更新保留编号及创建时间，刷新更新时间。未知字段被忽略，提交的编号、时间、长度、数量和航点序号不会覆盖系统结果。

`length` 是相邻航点水平大圆距离之和，单位米；不包含高度差，不自动闭合。共享工具 `src/utils/airline.ts` 使用 Haversine 算法及平均地球半径 `6371008.8` 米，前端预览可直接复用。接口保留计算精度，页面负责格式化展示。

## Mock 与页面接入

设置现有环境变量 `VITE_USE_MOCK=true` 后启动开发服务；生产 Mock 也使用现有自动注册机制。Mock 提供 12 条固定样例供列表分页，每条航线包含按固定经纬度偏移生成的 5 个航点，高度统一为 60 米，速度为 5 米/秒。写操作会修改运行时内存，开发服务重启、Mock 模块重载或生产 Mock 页面重新加载后恢复样例，不做持久化。

绘制、拖动、排序、删除航点、批量改高度、地图定位和预览均在前端维护未保存状态。结束绘制不会调用保存接口，用户点击保存后一次提交全部内容。

航线接口不保存所属场地或统一高度，不校验圈层和场地范围；删除航线不操作场地数据。本期不增加飞行执行或实时告警接口。

## 代码位置与调用顺序

已完成模拟数据、类型、API 封装和业务校验，并接入航线管理列表及编辑工作区。页面执行流程、代码位置和验收范围见[航线管理页面](./航线管理页面.md)。

| 文件 | 职责 |
| --- | --- |
| `src/pages/system-management/airline-management/types.ts` | 航点、表单、列表摘要、详情和分页参数的简单类型 |
| `src/api/airlineManagement.ts` | 页面直接调用的 5 个 API 方法 |
| `mock/system-management/airline.mock.ts` | 12 条固定样例、筛选分页、增删改查和保存校验 |
| `src/utils/airline.ts` | `calculateAirlineLength(waypoints)`，供 Mock 保存和页面预览共用 |
| `tests/airlineMock.test.ts` | 分页搜索、保存规则、系统字段保护和长度算法验证 |

调用链路为：页面调用 API 方法 → `request` 添加 `/api` 前缀 → Mock 匹配路由并处理 → 返回 `{ code, message, data }` → `request` 返回 `data`，业务错误则抛出 `Error(message)`。

```ts
import {
  getAirlineDetail,
  getAirlineList,
  createAirline,
} from "@/api/airlineManagement";

// 列表只返回摘要。查询条件变化或页面卸载时，可通过 signal 取消旧请求。
const result = await getAirlineList({ name: "滨江", page: 1, pageSize: 10 });
const detail = await getAirlineDetail("airline-001");

// 地图和表格先修改页面中的未保存数据，点击保存时再提交全部航点。
const saved = await createAirline({
  name: "滨江巡检航线",
  speed: 5,
  waypoints: [
    { longitude: 120.2102, latitude: 30.2074, altitude: 0 },
    { longitude: 120.2152, latitude: 30.2094, altitude: 80 },
  ],
});
```

运行 `pnpm test` 验证接口业务规则，运行 `pnpm lint` 和 `pnpm build` 检查代码及构建。开发服务启用 Mock 后，可直接请求 `GET /api/system-management/airlines?page=1&pageSize=10` 检查实际响应。
