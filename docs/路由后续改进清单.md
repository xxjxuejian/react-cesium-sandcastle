# 路由后续改进清单

本文记录当前动态权限路由方案的后续改进项。当前方案可以继续使用，不需要立即重写；后续按优先级逐项完善即可。

## 当前方案基线

- 顶层路由固定包含 `/login` 和受保护区域 `/*`。
- 登录或恢复会话后，后端返回当前用户的 `BackendRouteItem[]`。
- Zustand 保存认证状态、用户信息和授权路由。
- `transformRoutes` 将授权路由转换为 React Router 路由对象。
- `useRoutes` 在授权路由变化后重新匹配和渲染页面。
- 同一份授权路由同时用于生成侧边菜单、移动端菜单和面包屑。
- `import.meta.glob("../pages/**/index.tsx")` 只允许加载项目中已经打包的页面组件。

## P0：确保服务端真正执行权限校验

### 问题

前端动态路由只能控制页面入口和菜单展示，不能代替服务端权限控制。用户即使看不到页面，仍可能直接调用接口。

### 改进方向

- 所有需要权限的业务接口都根据当前登录用户校验角色或权限码。
- 后端不能仅依赖前端提交的角色、用户 ID 或路由名称。
- 未登录请求统一返回认证失败，已登录但权限不足的请求统一返回权限不足。
- 前端请求层区分认证失效和权限不足，分别执行重新登录或提示无权限。

### 验收标准

- 普通用户直接请求管理员接口时，服务端拒绝请求。
- 修改浏览器中的路由数据或手动输入管理员页面地址，不能绕过接口权限。
- 认证失效与权限不足在前端具有不同的处理结果。

## P1：增加后端路由数据的运行时校验

### 问题

TypeScript 类型只在编译阶段有效，不能保证接口在运行时返回的路由结构正确。错误的路径、重复路由或不存在的组件目前可能只表现为 404。

### 改进方向

在会话或登录结果写入 Zustand 前，对 `BackendRouteItem[]` 做递归校验：

- `path` 必须是非空相对路径，子路由不能以 `/` 开头。
- `name` 必须非空，并根据项目约定检查是否全局唯一。
- 拼接后的完整路径不能重复。
- `component` 必须能命中 `src/router/transform.tsx` 中的 `pageModules`。
- 有 `redirect` 时，目标地址必须存在于当前授权路由树中。
- 没有 `component` 的父路由必须至少包含一个子路由。
- 限制异常嵌套深度，防止错误数据造成无限递归或难以维护的菜单结构。
- 校验失败时记录明确的路由名称、字段和错误原因。

建议将校验逻辑放在独立模块中，例如：

```text
src/router/validateRoutes.ts
```

### 验收标准

- 不存在的组件路径能在开发环境中得到明确错误信息。
- 重复路径、非法相对路径和无效重定向不会进入路由状态。
- 登录与会话恢复使用同一套校验逻辑。
- 校验逻辑有独立自动化测试。

## P1：取消对 `/home` 的硬编码依赖

### 问题

根地址跳转和登录失败回跳目前都固定使用 `/home`。如果以后某个角色没有首页权限，会进入 404 页面。

### 改进方向

推荐按以下顺序确定用户默认页面：

1. 使用后端明确返回的默认首页，并确认该地址属于当前授权路由。
2. 如果没有配置默认首页，则查找当前路由树中第一个可访问的叶子路由。
3. 如果用户没有任何业务路由，则显示专门的“暂无可用权限”页面，而不是普通 404。

可以抽取统一函数，供根地址跳转和登录回跳共同使用，例如：

```ts
getDefaultRoutePath(routes: BackendRouteItem[]): string | null
```

### 验收标准

- 没有 `/home` 权限的用户仍能进入自己的第一个可访问页面。
- 空权限用户不会发生重定向循环。
- 根地址访问、登录成功和无效回跳使用同一套默认页面规则。

## P1：让授权回跳支持参数路由

### 问题

当前 `hasRoutePath` 使用完整字符串相等判断。未来如果出现 `users/:id` 之类的参数路由，`/users/123` 会被误判为不在权限路由中。

### 改进方向

- 使用 React Router 的 `matchPath` 或 `matchRoutes` 匹配路由模式。
- 统一处理尾部斜杠、查询参数和 Hash 中的地址。
- 明确通配符路由是否允许作为登录后的回跳目标。
- 对外部地址和协议开头的地址保持拒绝，避免开放重定向问题。

### 验收标准

- `/users/:id` 可以正确匹配 `/users/123`。
- 未授权参数路由仍然不能作为登录回跳目标。
- 查询参数可以保留，并且不会影响路径权限判断。

## P1：改进组件映射失败时的诊断

### 问题

当 `component` 无法命中 `pageModules` 时，目前直接渲染 `NotFound`，容易把配置错误误认为普通地址不存在。

### 改进方向

- 开发环境输出包含 `name`、`path`、`component` 的明确错误。
- 生产环境将错误上报到监控系统，但不向用户暴露内部文件路径。
- 根据产品需要区分“地址不存在”“无访问权限”和“页面配置错误”。
- 路由转换函数尽量不要静默吞掉配置错误。

### 验收标准

- 开发人员可以从一条错误信息定位到具体路由配置。
- 普通用户看不到源码目录等内部实现细节。
- 404、403 和配置异常具有明确且稳定的展示策略。

## P2：减少重复工具逻辑

### 问题

路径拼接、规范化和递归遍历目前分散在路由入口、菜单和面包屑等模块中。规则变化时容易出现不同步。

### 改进方向

- 抽取统一的 `joinRoutePath` 和 `normalizeRoutePath`。
- 复用统一的路由树遍历能力，例如查找默认页面、匹配面包屑和检查重定向目标。
- 只抽取确实被多个模块复用的逻辑，避免为单次调用增加包装层。

建议放置位置：

```text
src/router/pathUtils.ts
```

### 验收标准

- 菜单、面包屑和权限回跳使用相同的路径规范化规则。
- 删除各模块中重复的斜杠处理代码。
- 相关路径工具具备边界情况测试。

## P2：稳定懒加载组件实例

### 问题

`transformRoutes` 每次重新执行时都会调用 `lazy()` 创建新的组件类型。当前路由通常只在登录、会话恢复和退出时变化，因此影响较小；如果以后频繁刷新权限路由，可能造成当前页面不必要地重新挂载。

### 改进方向

- 按 `component` 路径缓存 `React.lazy` 生成的组件。
- 权限未发生实质变化时，避免写入新的 `routes` 数组引用。
- 只有性能分析确认存在重复挂载时再实施，不提前增加复杂度。

### 验收标准

- 相同组件路径在多次路由转换中复用同一个懒加载组件类型。
- 刷新等价权限数据时，当前页面不会无故丢失局部状态。

## P2：完善加载和异常边界

### 改进方向

- 统一会话恢复、布局加载和页面加载的视觉反馈。
- 为懒加载失败增加错误边界和重试入口。
- 区分网络加载失败、组件配置错误和普通 404。
- 保证加载失败后用户仍能退出登录或返回可访问页面。

### 验收标准

- 模拟页面代码块加载失败时，应用不会出现空白页。
- 用户能看到可理解的错误信息和恢复操作。

## P2：清理调试日志

发布前检查并移除以下无条件输出：

- `src/router/index.tsx` 中的登录状态和 `router` 日志。
- `src/router/transform.tsx` 中的 `pageModules` 日志。
- `src/store/auth.ts` 中的会话恢复日志。

需要长期保留的诊断信息应通过统一日志工具控制，并区分开发与生产环境。

## 推荐实施顺序

1. 确认并补齐服务端业务接口权限校验。
2. 增加路由数据运行时校验和对应测试。
3. 抽取默认路由计算，移除 `/home` 硬编码。
4. 使用路由模式匹配替换 `hasRoutePath` 的字符串相等判断。
5. 改进组件映射失败、403 和 404 的诊断与页面展示。
6. 统一路径工具并补充边界测试。
7. 根据实际性能和错误监控结果决定是否增加懒加载缓存、错误边界等优化。
8. 发布前清理调试日志。

## 每次改进后的回归检查

- [ ] 管理员可以访问全部授权页面。
- [ ] 普通用户看不到且无法访问管理员页面。
- [ ] 刷新受保护页面后能恢复会话并停留在原地址。
- [ ] 未登录访问受保护页面时会跳转登录，登录后能安全回跳。
- [ ] 无效或无权限的回跳地址会进入当前用户的默认页面。
- [ ] 根地址能进入当前用户实际拥有的默认页面。
- [ ] 菜单、移动端菜单和面包屑与授权路由保持一致。
- [ ] 父路由重定向和多级子路由正常工作。
- [ ] 不存在的页面、权限不足和配置错误表现符合约定。
- [ ] 中文和英文菜单标题正常显示。
- [ ] 执行 `pnpm lint`。
- [ ] 执行 `pnpm build`。
- [ ] 手动检查浏览器控制台没有遗留调试日志或未处理异常。
