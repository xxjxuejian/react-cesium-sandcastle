# 重点单位管理接口

更新日期：2026-10-31。

当前实现包含 API 封装和 Mock，不包含真实数据库。开发服务显式开启 `VITE_USE_MOCK=true` 后自动注册 `mock/system-management/keyUnit.mock.ts`；生产 Mock 也沿用现有自动发现机制。

## 页面使用与代码位置

管理员从“系统管理 → 重点单位管理”进入，路由为 `/system-management/key-unit-management`。列表支持名称搜索、重置、刷新和分页；新增、编辑、查看在当前路由内切换工作区，返回保留查询条件与页码。删除需要确认。

工作区以地图为主，右侧为可收起的参数栏，窄屏时参数栏移至地图下方。新增先填写基本信息，再设置三个圈；中心点、半径和最高高度初始留空，最低高度为 0。查看模式仅允许浏览和定位。

圈层识别配色统一为核心圈红色 `#EF4444`、反制圈橙色 `#F59E0B`、警戒圈青蓝色 `#06B6D4`。地图边线与半透明填充、参数栏标识及高度示意共用 `DEFENSE_RINGS` 配置，颜色仅区分防御类型，不代表已经触发告警。

二维地图支持点击和拖动共同中心及当前圈半径；三维只预览上下边界，高度通过参数输入修改。“完成调整”保留本次草稿，“取消调整”恢复本次调整前的数据，均不调用保存接口。只有“保存重点单位”整体提交，失败保留输入。

重点单位地图在二维和三维模式下统一使用较缓的缩放设置：`zoomFactor = 1.5`、`inertiaZoom = 0.2`，降低滚轮缩放幅度和松手后的惯性。配置在页面场景中设置，卸载时恢复原值。

存在未保存修改时，返回列表、切换路由及刷新关闭均有离开保护；保存期间阻止路由切换。模式与底图切换使用同一个 Viewer；离开时清理本页实体、监听器并恢复布局和相机输入。

## 接口与响应

基础路径为 `/api/system-management/key-units`，前端 `request` 自动添加 `/api` 并解包 `data`。

| 方法 | 路径 | 前端函数 |
| --- | --- | --- |
| GET | `/` | `getKeyUnitList(params, signal)` |
| GET | `/:id` | `getKeyUnitDetail(id, signal)` |
| POST | `/` | `createKeyUnit(values)` |
| PUT | `/:id` | `updateKeyUnit(id, values)` |
| DELETE | `/:id` | `deleteKeyUnit(id)` |

响应统一为 `{ code, message, data }`。成功为 `0`，参数错误为 `40004`，记录不存在为 `40404`。失败时 `data` 为 `null`，`message` 指明需修正的字段或包含关系。删除成功返回 `true`。

## 查询与分页

- `name?: string`：去除首尾空白后忽略大小写模糊匹配；省略或空白时查询全部。
- `page?: number`：从 1 开始的安全整数，默认 1。
- `pageSize?: number`：1～100 的整数，默认 10。
- 返回 `{ list, total }`，先筛选再分页，按更新时间倒序、编号升序排列；超出末页返回空数组及筛选后的总数。
- 列表每条包含 `id`、`name`、`longitude`、`latitude`、`address`、`rings`、`updatedAt`；详情增加 `remark` 和 `createdAt`。

## 保存结构与校验

新增与更新使用相同结构，更新整体替换可编辑字段：

```json
{
  "name": "某市政府",
  "longitude": 120.2,
  "latitude": 30.25,
  "address": "行政中心",
  "remark": "仅为字段示例",
  "rings": {
    "core": { "radius": 300, "minHeight": 0, "maxHeight": 120 },
    "counter": { "radius": 800, "minHeight": 0, "maxHeight": 200 },
    "warning": { "radius": 1500, "minHeight": 0, "maxHeight": 300 }
  }
}
```

数值只是示例，不代表布防标准或新增默认配置。

- 名称去除首尾空白后不能为空，允许同名；位置描述和备注以字符串提交，未填写时传空字符串。
- 经纬度使用 WGS84 度数，经度 -180～180、纬度 -90～90。`null` 和缺失值不能当成零坐标。
- 三层类型固定为 `core`、`counter`、`warning`，必须恰好各一个。
- 半径、最低和最高高度均为有限数值，单位为米。地面统一视为 0 米，接口直接保存高度，不增加起飞点或真实地面偏移。
- `0 < 核心半径 < 反制半径 < 警戒半径`。
- 每层 `0 ≤ minHeight < maxHeight`；下界满足 `警戒 ≤ 反制 ≤ 核心`，上界满足 `核心 ≤ 反制 ≤ 警戒`。
- `validateKeyUnit()` 同时供页面和 Mock 使用。参数暂时不完整或包含关系错误时，页面保留输入并阻止保存，Mock 再次校验。
- 编号为系统生成的 UUID；创建和更新时间使用北京时间 `YYYY-MM-DD HH:mm:ss`。请求伪造的编号、时间和多余字段不会覆盖系统结果，圈层也只复制已定义的三个数值。
- 更新保留编号和创建时间。接口返回副本，调用方修改返回数据不会直接改动 Mock 内存。
- 删除重点单位不修改航线或避难场所数据；不存在的详情、更新、删除均返回明确错误。

## 状态与持久化边界

Mock 提供 12 条固定演示记录，新增、更新和删除仅影响当前运行时内存。开发服务重启或 Mock 模块重载、生产 Mock 页面重新加载后，演示记录恢复；这不等于数据库持久化。

表单里的清空值用 `null` 表示；只有整体校验通过后才按 `KeyUnitFormValues` 提交。地图完成或取消调整不会发送保存请求。圈层预览需要控制数值规模，超过 1000 万米的范围会跳过地图绘制并提示；此限制保护渲染，不是保存接口的业务上限。
