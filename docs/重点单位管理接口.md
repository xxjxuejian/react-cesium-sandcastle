## 启动与数据升级

新增迁移为后端 `migrations/004_create_key_units.sql`，仅建立 key_units 表，保留用户、会话、避难场所和航线。本轮已在当前开发数据库执行迁移，其他环境先运行 `pnpm db:migrate`，再启动后端 `pnpm dev`。前端运行 `pnpm dev`，默认通过 `/api` 代理访问本机 3000 端口。

管理员登录或刷新恢复会话后，可进入“系统管理 → 重点单位管理”。新表不自动写入演示单位。普通用户没有管理菜单，直接调用全部管理接口均返回 403。

## 接口与响应

基础路径为 `/api/system-management/key-units`。前端 `src/api/keyUnitManagement.ts` 沿用五个 API 方法，`request` 添加 `/api` 和 Bearer token，并解包响应的 data。

| 方法 | 相对路径 | API 方法 | 成功响应 data |
| --- | --- | --- | --- |
| GET | 空路径 | `getKeyUnitList(params?, signal?)` | `{ list, total }` |
| GET | `/:id` | `getKeyUnitDetail(id, signal?)` | 完整记录 |
| POST | 空路径 | `createKeyUnit(values)` | 新增后的完整记录 |
| PUT | `/:id` | `updateKeyUnit(id, values)` | 更新后的完整记录 |
| DELETE | `/:id` | `deleteKeyUnit(id)` | `true` |

五个接口均检查有效会话与管理员角色。原始响应为 `{ code, message, data }`，成功 code 为 0。参数错误使用 HTTP 400、code 40004；记录不存在使用 HTTP 404、code 40404。无会话为 HTTP 401，无权限为 HTTP 403。全局 JSON 解析、请求体大小和异常处理继续使用 40000、41300、50000 等业务码。失败时 data 为 null，message 说明字段或包含关系。

## 列表与详情

name 为最多 100 个字符的名称筛选，去除首尾空白后按普通子串匹配，忽略英文大小写；空白或省略表示全部。百分号和下划线按普通字符处理。page 默认 1，pageSize 默认 10，必须为正整数且单页不超过 100。先筛选计数，再按更新时间倒序、编号升序稳定分页，超过末页返回空数组及筛选后的总数。

列表每条包含 id、name、longitude、latitude、address、rings、updatedAt。详情另外返回 remark 和 createdAt。列表 SQL 不读取备注和创建时间；圈层摘要仍包含完整三层半径与上下高度，符合现有页面契约。

## 保存结构与规则

新增和更新均提交完整资料，PUT 整体替换可编辑字段及圈层：

```json
{
  "name": "某市政府",
  "longitude": 120.2,
  "latitude": 30.25,
  "address": "行政中心",
  "remark": "仅为字段示例",
  "rings": {
    "core": { "radius": 300, "minHeight": 20, "maxHeight": 120 },
    "counter": { "radius": 800, "minHeight": 10, "maxHeight": 200 },
    "warning": { "radius": 1500, "minHeight": 0, "maxHeight": 300 }
  }
}
```

示例数值不代表布防标准，也不是新增时的默认配置。

- name 去除首尾空白后为 1～100 个字符，允许同名。
- address 与 remark 必须为字符串，分别最多 500 和 2000 个字符；未填写时提交空字符串。服务端去除首尾空白，不接受 null 或缺失值。
- 三层共用一个 WGS84 中心，经度 -180～180 度、纬度 -90～90 度；必须是有限数值。零坐标合法，null、字符串和缺失值不能转换成零。
- rings 必须恰好包含 core、counter、warning 各一个。每层必须具备 radius、minHeight、maxHeight 三个有限数值。
- 半径满足 `0 < 核心圈 < 反制圈 < 警戒圈`，单位米。
- 每层满足 `0 ≤ minHeight < maxHeight`，单位米，全部高度相对统一地面零平面，不叠加地形或起飞点偏移。
- 外层空间必须包含内层：下界为 `警戒 ≤ 反制 ≤ 核心`，上界为 `核心 ≤ 反制 ≤ 警戒`。允许各层共享相同高度边界，半径仍须严格递增。

前端 `validateKeyUnit()` 用于及时反馈，后端独立校验相同规则。不会自动修改其他圈层以凑出合法关系。地图对超过 1000 万米的范围跳过绘制并提示，这只是渲染保护，不是接口业务上限；后端保留有限数值及包含关系约束。

后端生成 UUID、创建时间和更新时间。数据库内部保存 UTC，接口返回北京时间 `YYYY-MM-DD HH:mm:ss`。更新保留 id、createdAt；请求伪造的编号、时间、颜色、圈层圆心和其他未知字段都不会覆盖系统结果。共同中心及完整三层参数在一条 INSERT 或 UPDATE 中保存，SQL 失败时整体回滚。删除单位不操作航线或避难场所。

## 页面流程与代码阅读顺序

1. `src/pages/system-management/key-unit-management/index.tsx` 管理列表、详情、保存与删除；异步查询取消旧请求，查看、编辑前单独请求详情。
2. `KeyUnitEditor.tsx` 维护唯一草稿，基本资料、地图中心及三层参数共用这份数据；`src/utils/keyUnit.ts` 提供前端校验、文字长度限制与圈层配色。
3. 二维地图通过“设置单位位置”和“地图调整半径”修改草稿。“完成调整”保留本次草稿，“取消调整”恢复调整前参数，均不调用保存接口。
4. 三维预览显示上下边界，参数不变；二维与三维切换使用同一 Viewer。新增中心、半径和最高高度留空，最低高度为零，由用户明确填写。
5. 点击“保存重点单位”后，API 经请求拦截器和 Vite 代理进入后端 `src/app.ts` 注册的 `src/modules/key-units/routes.ts`。
6. 路由检查会话及管理员身份，`service.ts` 白名单校验并将 rings 转成 JSON 保存，读取后还原对象；`types.ts` 解释单位、摘要与详情字段。后端不导入前端仓库文件。

保存失败显示后端消息并保留草稿。返回、路由切换及刷新关闭有未保存保护；只读查看允许浏览和定位，禁用资料及范围编辑，不发写请求。地图卸载时清理本页实体、事件和图层，并恢复相机输入与布局。

核心圈红色 `#EF4444`、反制圈橙色 `#F59E0B`、警戒圈青蓝色 `#06B6D4` 只用于区分类型，不代表告警。无人机实时接入、飞行执行和告警仍属于后续范围，见[无人机模拟飞行与告警规划](./无人机模拟飞行与告警规划.md)。
