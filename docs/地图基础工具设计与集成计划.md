## 一、结合当前结构的结论

采用“现有地图底座＋可复用工具逻辑＋默认工具栏＋页面业务交互”的组合方式。

当前代码已具备集成条件：

| 当前模块                                                        | 已有职责                                            | 集成方式                                          |
| --------------------------------------------------------------- | --------------------------------------------------- | ------------------------------------------------- |
| `src/components/CesiumMap/CesiumMap.tsx`                        | 创建、销毁 `Viewer`，提供局部 Context，处理基础错误 | 保持现有职责，工具通过 `useCesium()` 获取当前地图 |
| `src/pages/system-management/airline-management/AirlineMap.tsx` | 绘制航点、处理选择和拖动                  | 底图交给公共工具，仅显示底图入口，默认天地图    |
| `src/pages/hangzhou/boundaries/index.tsx`                       | 地形、行政区、悬停选择、下钻与返回                  | 组合公共工具，测量期间暂停行政区鼠标交互          |

杭州边界页接入底图和测量，航线页仅接入底图。公共测量逻辑包含二维、三维取点分支，二维分支已通过自动化验证，实际二维测量的浏览器验收留到后续接入测量时完成。

这次提取有明确价值：底图切换、测量流程及资源清理都需要跨页面复用。增加的理解成本主要是两个 Hook 与工具栏之间的调用关系，因此只按能力拆分，保持执行流程直观。

## 二、工具 UI 与执行逻辑怎样组织

新增 `src/components/CesiumMapTools/`，提供三个主要公开接口：

| 接口                              | 负责什么                                                   | 页面怎样使用                                                               |
| --------------------------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------- |
| `useBasemap()`                    | 地图来源和图层类型状态、图层创建与切换、可用项、错误和清理 | 默认工具栏或页面自定义按钮调用 `setSource()`、`setType()`                  |
| `useMapMeasurement({ disabled })` | 测量状态、取点、计算、图形及结果管理                       | 调用 `start()`、`finish()`、`cancel()`、`removeResult()`、`clearResults()` |
| `MapToolbar`                      | 按钮、底图面板、操作提示、测量结果列表                     | 接收上述状态与回调，可配置工具种类和容器样式                               |

UI 通过回调调用工具逻辑；工具逻辑通过当前地图的 `Viewer` 操作 Cesium。

默认集成关系为：

```text
CesiumMap
└── 页面场景组件
    ├── useBasemap()
    ├── useMapMeasurement()
    ├── 页面自己的航点／行政区逻辑
    └── MapToolbar
```

两个 Hook 都在 `CesiumMap` 已就绪的后代中调用。工具栏只接收状态和操作回调，因此页面未来可以替换按钮布局，继续复用相同逻辑。

默认 UI 使用简单文字按钮，颜色通过 `theme.useToken()` 跟随现有 Ant Design 主题，使用工具专属样式控制定位与间距：

- 桌面在地图右侧中部放置紧凑竖排工具按钮，面板在左侧展开；窄屏采用底部横排，面板在上方展开。区县详情在窄屏下上移，避开工具栏和底部来源署名。
- 工具包含底图切换、测距、测面积和结果入口，清空放在结果面板中。底图面板使用“地图来源”和“图层类型”两组普通单选项，来源选择 OSM 或天地图，类型选择矢量图或影像图。
- 面板根据当前来源显示可用类型；OSM 的影像图选项禁用并说明该来源不提供影像图，天地图未配置 Key 时禁用来源选项并提示配置。
- 测量期间显示当前类型、数值，以及“完成／取消”按钮。
- 结果列表显示编号、类型、数值，支持逐条删除。
- 页面通过启用项选择所需能力，通过容器样式调整位置；业务按钮仍由页面组织。
- 底图、结果和当前测量共用一个主面板位置。浏览底图或结果时保留草稿，收起浏览面板后恢复测量提示；也可点击“返回正在进行的测量”。
- 再次点击当前测量工具取消草稿；切换另一种测量工具会丢弃旧草稿并开始新测量，已完成结果保留。
- 底图和结果面板支持点击外部收起；焦点在工具栏内时按 `Esc` 收起浏览面板，并归还焦点给打开它的按钮，此时保留测量草稿。

## 三、点击以后实际执行什么

### 3.1 底图切换

地图来源与图层类型分别保存，默认值为 `source: "osm"`、`type: "vector"`；页面可传入初始来源，例如航线页使用 `useBasemap("tianditu")`，缺少 Key 时初始使用 OSM。`setSource()` 负责选择来源，`setType()` 负责选择当前来源支持的图层类型；UI 和 Hook 都需要检查组合是否可用，不能仅依赖按钮禁用。

支持的组合如下：

| 地图来源 | 矢量图                       | 影像图                       | Key 要求           |
| -------- | ---------------------------- | ---------------------------- | ------------------ |
| OSM      | 支持，使用当前标准道路底图   | 不支持，禁用对应选项         | 无需配置 Key       |
| 天地图   | 支持，加载道路底图及对应注记 | 支持，加载影像底图及对应注记 | 需要配置天地图 Key |

OSM 标准瓦片服务提供道路地图，不提供卫星影像；不将其他供应商的影像标记为 OSM。其标准瓦片服务说明见 [OSM 瓦片使用政策](https://operations.osmfoundation.org/policies/tiles/)。

切换地图来源的执行链路：

```text
点击地图来源“天地图”
→ 检查 Key 是否已配置
→ 调用 setSource("tianditu")
→ React 更新地图来源，并将图层类型设为 "vector"
→ Hook 中的场景副作用切换为天地图道路底图及对应注记
→ Cesium 请求瓦片并更新画面
```

在天地图中切换图层类型的执行链路：

```text
点击“影像图”
→ 调用 setType("imagery")
→ React 更新底图类型
→ Hook 中的场景副作用切换对应图层
→ Cesium 请求瓦片并更新画面
```

OSM 沿用 `OpenStreetMapImageryProvider` 和 `https://tile.openstreetmap.org/`。天地图道路底图和影像底图各自搭配对应注记，采用 WMTS 接入。Cesium 已提供相应的 [WMTS 加载接口](https://cesium.com/learn/cesiumjs/ref-doc/WebMapTileServiceImageryProvider.html)。

具体约定：

- 无论是否已配置天地图 Key，页面首次进入都默认显示 OSM 矢量图；首版不持久化上次选择。
- UI 标为“矢量图／影像图”，这里的“矢量图”指地图样式，本版按栅格瓦片加载。
- 沿用已有的 `VITE_TIANDITU_TOKEN` 配置天地图 Key，变量类型在 `src/vite-env.d.ts`，示例在根目录 `.env.example`；在 `.env.local` 填写后重启开发服务。OSM 不依赖此配置。
- 未配置 Key 时保留 OSM 正常使用，禁用天地图来源选项并提示配置；配置后可由用户主动切换。
- 切换到不同来源时，图层类型统一设为矢量图；从天地图影像图切回 OSM 时，也必须同步更新类型，避免 UI 与实际底图不一致。
- 工具只管理自己创建的底图与注记，放在业务影像层下方。
- 切换地图来源或图层类型时，保持相机、航点、行政区、地形和测量结果，保留当前来源署名。
- 瓦片加载失败时提示错误并提供重试，不将整个地图标记为运行失败，也不自动改为其他来源；用户可以主动切回 OSM。

制定计划时，天地图官方服务文档访问超时；真实加载、级别配置及注记对齐必须经过浏览器验收，不能将 API 方案核对当作在线服务已经验证。

### 3.2 距离与面积测量

执行链路：

```text
点击“测距”
→ 调用 start("distance")
→ 进入测量状态，暂停页面业务取点
→ 注册测量鼠标事件
→ 点击确定顶点，移动鼠标预览下一段
→ 点击“完成”或右键结束
→ 保存结果，移除本次测量事件
→ 恢复普通浏览
```

第一版采用忽略高度与地形起伏的水平量测：

- 距离：至少两个有效顶点，累加相邻点的球面距离。
- 面积：至少三个有效顶点，自动闭合，计算球面多边形面积。
- 使用独立的计算函数，按模块引入 `@turf/distance`、`@turf/area`、`@turf/kinks`，分别处理距离、面积及自交检查。参考[距离文档](https://turfjs.org/docs/api/distance)、[面积文档](https://turfjs.org/docs/api/area)、[自交检查文档](https://turfjs.org/docs/api/kinks)。
- 二维通过 `camera.pickEllipsoid()` 取点；三维优先使用 `globe.pick()` 取地表位置，失败时回退到椭球，再提取经纬度进行水平计算，不使用模型深度或航点相对高度。
- 无法拾取地球位置时不添加点；与上一顶点相距不足 1 厘米的点击不增加顶点。面积还会拒绝重复顶点、自交、经纬度共线等退化形状，以及不大于 0.01 平方米的面积。
- “完成”按钮只根据已确定顶点数启用；真正完成时继续检查形状。校验失败会提示原因并保留草稿，用户可以补点或取消。
- 预览数值包含鼠标当前指向的临时点，最多每 100 毫秒更新一次；完成结果只使用点击确定的顶点，右键位置和未点击的预览点不写入结果。
- `Esc` 取消当前草稿；取消不删除已完成结果。焦点位于底图／结果面板时优先收起面板；输入框、选择框、可编辑内容或对话框中的键盘事件由对应界面处理。
- 保留多组结果，支持逐条删除和清空；清空会同时取消草稿。结果编号在当前地图内递增，清空后不复用；离开页面后清除，不写入航线数据。
- 内部统一使用米、平方米，显示时转换为米／千米、平方米／平方千米。
- 面积工具面向普通局部区域：经度跨度大于 180 度、存在绝对纬度大于 85 度的顶点时禁止完成；不支持带孔多边形和地形表面积。距离按相邻点的大圆距离累加，不套用上述面积范围限制。

地形对测量的影响（2026-10-28 补充）：

| 环节 | 开启地形后的实际行为 |
| --- | --- |
| 取点 | 三维模式优先拾取地形表面的位置，但只保存经纬度，丢弃高度。地形会影响鼠标射线与地表的交点。 |
| 数值计算 | 测距累加相邻经纬度之间的球面距离，测面积计算球面多边形面积；两者均不使用地形高度，也不沿地形采样。 |
| 图形显示 | 测量折线、顶点和标签贴地显示，可以随山坡起伏；图形贴地不代表数值包含地形起伏。 |

例如，跨山谷测距不会累计下坡、上坡的实际路程，圈住山坡测面积也不会计算山坡的实际表面积。对于完全相同的经纬度顶点，开启或关闭地形不改变计算结果；但同一个屏幕位置可能拾取到不同的经纬度，重新点击测量时数值可能因此间接变化。

对应代码为 `useMapMeasurement.ts` 中的 `pickPosition()` 和贴地显示配置，以及 `measurement.ts` 中的 `calculateDistance()`、`calculateArea()`。

测量图形统一放入工具专属 `CustomDataSource`。鼠标预览坐标和 Cesium 对象放在 Ref 中，React 状态保存界面需要展示的模式、数值与结果。

## 四、怎样协调现有页面交互

采用互相禁用的规则：

本轮已实现杭州边界页的交互协调。下表中的航线绘制，以及下方 `AirlineEditor` 的通知、只读和保存规则，作为后续接入约定保留，本轮不修改航线页。

| 当前操作 | 页面业务交互                                     | 公共工具                 |
| -------- | ------------------------------------------------ | ------------------------ |
| 普通浏览 | 正常选择、拖动或悬停                             | 可以开始测量、切换底图   |
| 航线绘制 | 正常添加航点                                     | 禁用测距与测面积         |
| 测量     | 暂停航点选择、拖动、区县悬停和点击；禁用开始绘制 | 正常取测量点、完成或取消 |
| 测量完成 | 恢复普通浏览                                     | 保留结果，可继续测量     |

集成时需要处理以下具体问题：

- 航线页通过回调把“正在测量”通知 `AirlineEditor`，用于禁用绘制按钮；保存期间取消测量草稿并禁用新测量。只读查看仍允许使用基础工具。
- 页面事件回调读取最新测量状态，避免因切换工具重新加载行政区或重建航点事件。
- 杭州边界页进入测量时清除行政区悬停样式，保留已选区县，暂停悬停、点击、下钻及面包屑返回；完成或取消后恢复。通过 Ref 向已有事件传递最新模式，场景加载 Effect 不因工具状态变化而重跑。
- 后续接入航线页时，页面还需结束已有拖动并恢复相机输入；当前公共 Hook 不负责航点拖动状态。
- 已完成的测量图形可能遮挡业务对象。边界页使用 `drillPick()`，按 `MEASUREMENT_ENTITY_PREFIX` 跳过测量实体，检查第一个其余拾取对象；只有区县面与标签可选中，边界线仍会阻断拾取并清除选中，不穿过界线选择下方区县。航点的拾取协调留待后续接入。
- 平移、缩放继续可用。测量期间临时暂停默认双击动作，退出时恢复进入前的设置。
- 开始测量时取消当前相机飞行。切换底图只替换本工具创建的图层与错误监听；结束或取消测量只移除草稿和本次输入监听，恢复光标与双击动作。完成结果保留到删除、清空或卸载；卸载时移除工具自己的数据源与图层，并调用 `requestRender()`，普通 React 重渲染不清空资源。

首版使用简单状态与回调协调，不增加全局工具 Store、工具注册中心或通用事件分发框架。
