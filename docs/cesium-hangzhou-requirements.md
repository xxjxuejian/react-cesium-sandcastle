# 杭州 Cesium 三维示例需求规划

> 文档状态：需求草案
>
> 规划主题：杭州城市应急与低空巡检
>
> 技术范围：CesiumJS 1.143、React 19、TypeScript、Vite
>
> 当前阶段：只定义需求、数据准备和实施边界，不包含代码实现

## 1. 文档目的

本文用于定义杭州 Cesium 三维示例的候选需求、优先级、数据准备、页面拆分、验收标准和风险边界，作为后续设计与实现的共同基线。

本项目首先是一个可逐步学习 CesiumJS 的案例集，同时保留沉淀薄基础层和复用业务能力的可能。它不是一次性大屏项目，也不在第一阶段追求生产级数字孪生平台。

## 2. 已确认的规划决策

根据前期讨论，采用以下决策：

1. 项目形态采用“学习案例集 + 可复用薄基础层”。
2. 业务主题采用“杭州城市应急 + 低空无人机巡检”。
3. 行政区、地形等地理数据优先使用真实数据；设备、事件和轨迹使用结构真实的模拟数据。
4. 行政区第一阶段做到“杭州市 → 区县”；街道/社区级只选择一个代表区深化。
5. Cesium 和 Three.js 分别设计，第一阶段不进行双引擎同场景渲染。
6. 先保证本地运行，再按公开部署的安全和授权要求设计资源配置。
7. 代表区暂定西湖区，因为它同时包含城市、湖泊和山地场景，适合验证地形、建筑、应急设施和低空路线；实施前可调整。

## 3. 仓库现状与约束

### 3.1 已有基础

- 项目已安装并锁定 `cesium@1.143.0`。
- 已配置 Cesium Workers、Assets、Widgets 等静态资源。
- 已通过环境变量接入 Cesium ion Token。
- 已实现通用 `CesiumMap`、`useCesium()` 和 `useCesiumEffect()`。
- `CesiumMap` 已负责 Viewer 创建、销毁、错误处理、尺寸变化和 React StrictMode 生命周期适配。
- 页面采用 React Router 懒加载，每个 Cesium 页面独立持有 Viewer。

### 3.2 继续遵守的架构原则

- `CesiumMap` 只管理地图容器和 Viewer 生命周期，不内置杭州业务能力。
- 地形、影像、行政区、建筑、设备、轨迹、交互和分析由对应页面组件或 Hook 管理。
- 谁创建 Cesium 资源，谁负责清理。
- Viewer 不放入 Zustand，不创建模块级全局单例。
- 示例页之间默认不共享场景状态，保证案例可以独立阅读和调试。
- 最终综合页可以复用案例沉淀的场景组件，但不能反向污染基础组件。

## 4. 产品形态

采用“独立学习页 + 综合演示页”的两层结构。

### 4.1 独立学习页

| 页面 | 核心学习目标 | 主要 Cesium 能力 |
| --- | --- | --- |
| 杭州基础场景 | 初始化地图并飞入杭州 | Viewer、Camera、Imagery |
| 杭州地形 | 展示真实地形并查询高程 | Terrain、Globe、sampleTerrain |
| 杭州行政区 | 边界、填充、高亮和下钻 | GeoJSON、Entity、Picking |
| 杭州建筑 | 加载并查询城市建筑 | 3D Tiles、Styling、Metadata |
| 应急设施 | 展示避难场所和设备 | Entity、DataSource、Clustering |
| 无人机巡检 | 三维轨迹、姿态和时间播放 | Clock、SampledPosition、CZML、Model |
| 空间分析 | 测量、地形剖面和通视实验 | Picking、Terrain Sampling、Spatial Math |

### 4.2 综合演示页

最终增加“杭州三维应急与低空巡检”综合页，组合已完成的稳定能力：

- 杭州市与区县行政边界。
- 地形、影像、建筑图层。
- 避难场所、监测设备、无人机起降点。
- 无人机实时位置和历史轨迹。
- 图层控制、区域筛选、状态筛选和时间播放。
- 区域、建筑、设备和无人机统一详情面板。

综合页不是第一阶段入口。只有独立案例达到验收标准后，才进入组合阶段。

## 5. 用户场景

### 5.1 市域总览

用户进入页面后，相机从较高视角飞入杭州市，看到市域边界、下辖区县、主要地形和业务状态概览。用户可以通过图例理解各区县的应急资源或事件分布。

### 5.2 区域下钻

用户移入区县时看到高亮和摘要，点击后相机飞入目标区县，地图只突出当前区域，并加载更详细的设施、建筑和无人机数据。用户可以通过面包屑返回杭州市。

### 5.3 应急设施查询

用户筛选避难场所、摄像头、环境传感器、通信基站和无人机起降点，点击对象查看状态、更新时间和业务属性。异常设备使用清晰但不过度干扰的告警样式。

### 5.4 无人机巡检回放

用户选择一项巡检任务，播放无人机沿三维航线运动的过程，查看速度、高度、姿态和任务阶段，并可切换全局、跟随和第一视角。

### 5.5 空间分析

用户可以测量两点距离、地形距离和高度差，查看路线地形剖面，或选择观察点执行实验性的通视/视域分析。

## 7. 数据准备

### 7.1 行政区数据

需要准备：

- 杭州市边界 GeoJSON。
- 杭州市下辖区县 GeoJSON。
- 西湖区街道或重点片区 GeoJSON，作为第二级下钻候选。
- 每个 Feature 至少包含 `name`、`adcode`、`level`、`parentAdcode`。

要求：

- 仓库内用于 Cesium 的坐标统一为 WGS84。
- 记录来源、下载日期、行政区版本和授权说明。
- 对 MultiPolygon、内环和飞地进行检查。
- 进行适度简化，但保留原始数据或可追溯来源。
- 不直接复用未经确认坐标系的高德边界结果。

### 7.2 地形与影像

第一阶段候选：

- Cesium World Terrain。
- Cesium ion 或其他允许公开展示的影像。

验证项：

- 杭州范围内的地形分辨率。
- 西湖水面、湖岸和山体的视觉质量。
- 影像、边界和设施点的对齐情况。
- Token 权限、配额、域名限制和公开部署许可。
- 中国大陆网络环境下的可用性和加载速度。

如果外部服务无法稳定满足要求，再评估自托管 terrain 与 imagery；自托管不属于第一版默认目标。

### 7.3 建筑数据

按以下顺序评估：

1. OSM Buildings：用于快速学习 3D Tiles 加载、拾取和样式。
2. 其他合规公开 3D Tiles：用于比较覆盖和元数据质量。
3. 自有白模、倾斜摄影或 BIM 转换数据：仅在明确数据来源后规划。

需要记录：

- 空间覆盖范围。
- 建筑高度和轮廓精度。
- Feature metadata 字段。
- 单次加载量和显存占用。
- 授权、署名和公开展示限制。

### 7.4 GLB 模型

至少准备：

- 一架带正确朝向基准的无人机模型。
- 一辆应急车辆模型。
- 一个摄像头或传感器设备模型。

模型要求：

- 使用 GLB，尺寸单位按米处理。
- 明确模型前向轴、上方向、原点和落地点。
- 控制三角面和纹理大小。
- 优先使用 KTX2/Basis 或合理压缩纹理。
- 记录模型来源与授权。

### 7.5 业务数据模型

统一业务对象建议：

```ts
type MapAsset = {
  id: string;
  type: "shelter" | "camera" | "sensor" | "station" | "droneBase" | "event";
  name: string;
  status: "online" | "offline" | "warning" | "maintenance";
  longitude: number;
  latitude: number;
  height?: number;
  districtCode: string;
  updatedAt: string;
  properties: Record<string, unknown>;
};
```

无人机轨迹点建议：

```ts
type DroneTrackPoint = {
  timestamp: string;
  longitude: number;
  latitude: number;
  height: number;
  speed?: number;
  heading?: number;
  pitch?: number;
  roll?: number;
  phase?: "takeoff" | "cruise" | "hover" | "return";
};
```

业务主数据保存 WGS84。高德二维项目所需的 GCJ-02 转换应由二维适配层完成，不修改共享主数据。

## 8. 技术能力与数据规模选择

| 场景 | 首选能力 | 适用边界 |
| --- | --- | --- |
| 行政区 GeoJSON | `GeoJsonDataSource` | 第一版、对象数量有限、需要逐区域交互 |
| 少量业务点位 | Entity / `CustomDataSource` | 易于绑定详情、状态和时间属性 |
| 大量静态点线面 | Primitive / 集合类 | Entity 成为性能瓶颈后再切换 |
| 大规模建筑 | `Cesium3DTileset` | 流式 LOD、元数据查询和样式 |
| 单个重点 GLB | Entity Model 或 `Model` | Entity 优先；复杂节点与动画控制再用 Primitive API |
| 无人机轨迹 | `SampledPositionProperty` / CZML | 带时间戳的动态位置和姿态 |
| 区域/建筑/模型拾取 | `ScreenSpaceEventHandler` + Scene picking | 需要统一判别不同对象类型 |
| 高程与剖面 | `sampleTerrain` 系列 | 批量采样并明确精度限制 |

第一版使用可读性更高的 Entity/DataSource API。只有在真实数据量和性能测量证明有必要时，才迁移到 Primitive。

## 9. 非功能需求

### 9.1 性能

- 默认启用按需渲染；时间播放、粒子或持续动画场景可按页面调整。
- 主要测试环境暂定桌面 Chrome、1920×1080、独立或中档集成显卡。
- 市域总览静止时应保持低 CPU/GPU 占用。
- 正常交互目标为不低于 30 FPS，推荐目标为 45 FPS 以上。
- 高 DPI 环境允许降低 `resolutionScale`。
- 建筑和地形质量优先通过屏幕空间误差与缓存参数调节，不无限追求最高精度。
- 业务对象按距离显隐；大批量点位必须聚合或切换底层实现。

上述性能数字为初始目标，正式基线要在确定测试设备和数据规模后更新。

### 9.2 稳定性与资源清理

- 离开页面后停止动画、时钟监听和网络更新。
- 销毁 ScreenSpaceEventHandler、DataSource、Primitive、3D Tiles 和模型等页面资源。
- 异步资源完成加载时页面若已卸载，不再加入 Viewer。
- 地形、影像、GeoJSON、3D Tiles、GLB 分别处理错误，不因单个图层失败使整个地图不可用。
- 图层失败后允许重试或降级隐藏。

### 9.3 安全与授权

- Token 不写入仓库。
- 浏览器可见 Token 只授予最小读取权限，并限制资产和允许来源。
- 公共部署前检查地形、影像、行政区、建筑和模型的授权及署名要求。
- 模拟业务数据不得使用真实个人、敏感设施或受限飞行信息。

### 9.4 可维护性

- 每个案例页面有独立入口、说明和验收点。
- 场景资源放入页面级 Hook 或无 UI 场景组件。
- React 只管理业务状态和 UI；Cesium 对象不直接进入可序列化 Store。
- 统一定义图层 ID、业务对象类型、状态色和选择状态。
- 路由、菜单和中英文文案同步维护。

## 10. MVP 范围

第一版综合 MVP 建议只包含：

1. 飞入杭州市并展示真实地形。
2. 展示杭州市和区县真实边界。
3. 行政区悬停高亮、点击详情和一级下钻。
4. 按模拟应急指标对区县分级设色。
5. 加载一个可用的杭州建筑数据源。
6. 加载约 30～100 个模拟设施点，支持类型与状态筛选。
7. 加载一架无人机和一条带时间戳、高度的三维轨迹。
8. 支持播放、暂停、倍速和相机跟随。
9. 提供图层面板、图例、详情面板和视角复位。
10. 单个图层失败时其余场景仍可使用。

不在 MVP 中加入：

- 全杭州市街道/社区级下钻。
- 多架无人机实时并发。
- 专业视域、淹没或路径规划算法。
- 自行生产倾斜摄影和 3D Tiles 数据。
- Cesium 与 Three.js 同场景渲染。
- 真实业务后台、WebSocket 和生产权限系统。

## 11. 实施阶段

### 阶段 0：数据与可行性验证

- 确认杭州/区县 GeoJSON 来源、坐标和授权。
- 验证 World Terrain 在杭州的效果。
- 验证建筑数据覆盖和元数据。
- 校验一个设施点在影像、边界和地形中的位置。
- 确认无人机 GLB 的尺寸、轴向和授权。

阶段出口：数据源可用，坐标无明显偏移，关键外部资源的权限与限制已记录。

### 阶段 1：杭州行政区案例

- 杭州市初始相机。
- 市域与区县 GeoJSON。
- 描边、填充、标签、悬停、点击。
- 区县分级设色。
- 一级下钻和返回。

阶段出口：行政区交互闭环完成，且资源清理正确。

### 阶段 2：地形与建筑案例

- 地形、贴地和高程查询。
- 建筑 3D Tiles 加载。
- 建筑悬停、点击和元数据展示。
- 图层加载和错误状态。

阶段出口：地形、边界、建筑对齐，建筑数据质量已有结论。

### 阶段 3：业务设施案例

- 统一业务数据模型。
- 避难场所与设备点位。
- 状态样式、筛选、详情和告警联动。
- 距离显隐或聚合策略。

阶段出口：30～100 个对象交互流畅，业务状态与地图联动正确。

### 阶段 4：无人机巡检案例

- 无人机 GLB。
- 时间动态轨迹与姿态。
- 播放控制、阶段颜色和相机跟随。
- 电子围栏和模拟告警作为 P1 增量。

阶段出口：完整轨迹可以稳定重复播放，暂停、重播和退出跟随无状态残留。

### 阶段 5：空间分析与综合页

- 距离、高度差、地形剖面。
- 组合已稳定的行政区、地形、建筑、设施和无人机能力。
- 统一详情面板、图层面板和筛选状态。
- 执行性能与移动端基础验证。

阶段出口：综合 MVP 验收通过，独立案例仍可以单独运行。

## 12. 验收清单

### 12.1 功能验收

- 初次进入可正确飞入杭州市。
- 市域和区县边界无明显错位。
- 区域悬停、选中、取消和下钻状态明确。
- 地形与贴地对象表现正确。
- 建筑图层可加载、隐藏、拾取和恢复样式。
- 设施筛选、列表和地图选择同步。
- 无人机轨迹可完整播放并显示正确高度。
- 图层失败不会导致整个 Viewer 崩溃。
- 一键重置可以恢复默认视角、筛选和选择状态。

### 12.2 生命周期验收

- React StrictMode 下没有重复监听或访问已销毁 Viewer 的错误。
- 在 Cesium 页面之间切换不会遗留事件、动画或 WebGL 上下文。
- 返回页面后 Viewer 和页面资源可以重新创建。
- 侧栏折叠和窗口缩放后画布尺寸正确。
- 异步加载完成晚于页面卸载时不会污染新场景。

### 12.3 工程验收

- `pnpm lint` 通过，或明确区分并记录历史遗留问题。
- `pnpm build` 通过。
- 新增路由、菜单和中英文文案保持一致。
- 关键数据和模型具有来源、坐标系与授权说明。
- 公开部署环境不暴露非必要权限的 Token。

## 13. 主要风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| WGS84、GCJ-02 数据混用 | 边界、影像和点位错位 | 共享主数据统一 WGS84，导入时校验并记录坐标系 |
| 行政区数据版本不明 | 名称、编码或边界过期 | 固化来源和日期，实施前核对行政区版本 |
| 杭州地形或影像质量不足 | 视觉效果与分析精度不足 | 阶段 0 先验证，保留更换 Provider 的边界 |
| 建筑覆盖或 metadata 不足 | 无法查询和专题着色 | 将公开建筑作为学习数据，不把完整属性列为硬性承诺 |
| Token、配额或网络失败 | 场景不可访问 | 最小权限、域名限制、错误提示和降级方案 |
| GeoJSON/Entity 数量过大 | 加载和交互变慢 | 简化数据、距离显隐，测量后再迁移 Primitive |
| 轨迹每帧手动更新 | CPU 占用和状态复杂 | 优先使用 SampledPositionProperty 或 CZML |
| 多个高频拾取处理器 | 鼠标移动卡顿 | 统一拾取入口、节流、限制 drillPick 数量 |
| 透明面、地形和建筑重叠 | 深度冲突或闪烁 | 合理高度偏移、贴地策略和透明度，减少重复表面 |
| 一开始建设综合大屏 | 学习目标和故障边界不清 | 先完成独立案例，再组合综合页 |

## 14. 实施前仍需确认的事项

以下事项不阻塞本文档成立，但应在对应阶段开始前确认：

1. 代表区是否最终采用西湖区。
2. 杭州行政区 GeoJSON 的正式来源和授权。
3. World Terrain 和候选影像在目标网络环境中的实际表现。
4. OSM Buildings 或其他 3D Tiles 在杭州的覆盖和元数据质量。
5. 无人机、车辆和设备 GLB 的来源。
6. 首版模拟设施数量和无人机轨迹采样频率。
7. 最终公开部署域名、Token 白名单和目标测试设备。
8. 综合页的视觉风格是偏学习工具、业务系统还是展示大屏。
