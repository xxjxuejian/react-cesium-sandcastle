# 避难场所接口与学习说明

更新日期：2026-11-07。对应阶段 4，前端 `frontend_single` 分支只连接真实后端。

## 启动与升级

后端新增迁移 `migrations/002_create_shelters.sql`，只新增 shelters 表，保留已有 users、sessions 和迁移记录。本轮已在当前开发数据库执行该迁移。其他环境先运行 `pnpm db:migrate`，再运行 `pnpm dev`；前端同样运行 `pnpm dev`。本阶段不自动创建演示场所，新库的场所列表为空。

登录或刷新恢复会话后，管理员菜单增加“避难场所管理”；普通用户不显示该菜单，直接请求五个接口均返回 403。

## 接口契约

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/system-management/shelters` | 筛选与分页列表 |
| POST | `/api/system-management/shelters` | 新增场所 |
| GET | `/api/system-management/shelters/:id` | 完整详情 |
| PUT | `/api/system-management/shelters/:id` | 整体更新资料 |
| DELETE | `/api/system-management/shelters/:id` | 删除场所 |

全部要求有效 Bearer 会话及管理员角色。成功返回 `{ code: 0, message, data }`：列表 data 为 `{ list, total }`，新增、详情及更新返回完整资料，删除返回 true。列表沿用前端已有的完整记录类型，不改成摘要。失败为真实 HTTP 状态和 `{ code, message, data: null }`，400 业务参数错误、401 会话失效、403 无权限、404 场所不存在；其余解析、大小和异常处理沿用全局规则。

列表支持 name、managementUnit、address 的字面子串匹配，不区分英文大小写；facilityType、shelterUsage、operationStatus 精确匹配。空白文本忽略，百分号和下划线按普通字符处理。page 默认 1，pageSize 默认 10，均为正整数，每页最多 100 条。先筛选计数，再按更新时间倒序、编号升序稳定分页；超过末页返回空数组和筛选后的总数。

## 保存规则

新增和更新都使用资料白名单，忽略请求伪造的 id、createdAt、updatedAt 等系统字段。名称允许重复。数据库保存 UTC 时间，接口显示北京时间 `YYYY-MM-DD HH:mm:ss`。

| 字段 | 规则 |
| --- | --- |
| name | 去除首尾空格，1～100 个字符 |
| facilityType | school、stadium、park、communityCenter、undergroundSpace、other |
| shelterUsage | temporary、longTerm、medicalAid、supplyDistribution、comprehensive |
| operationStatus | open、full、maintenance、closed |
| capacity、availableCapacity | 非负安全整数，单位人，可用容量不大于总容量 |
| facilities | 合法设施编码数组，可为空，不能重复 |
| address | 1～500 个字符 |
| location.longitude、latitude | 有限数值，经度 -180～180，纬度 -90～90，零坐标合法；null 和字符串不能转换成零 |
| location.height | 可选有限数值，单位米，零高度合法；省略或 null 表示清空 |
| managementUnit | 1～100 个字符 |
| contactName | 1～64 个字符 |
| contactPhone | 1 开头的 11 位手机号 |
| description | 可选文本，最多 2000 个字符；省略、null 或空白表示清空 |

设施编码包括 drinkingWater、foodSupply、medicalAid、toilet、powerSupply、communication、barrierFree、parking、warehouse。类型显示文字与颜色继续由前端 `constants.ts` 提供。

可选高度和备注在数据库保存为 NULL，在接口响应中省略。PUT 是完整资料更新，省略可选字段会清空，不沿用上次值。校验失败不会修改原记录；删除后再次读取、更新或删除均返回 404。

## 从入口读代码

一次保存从前端 `src/pages/system-management/shelter-management/index.tsx` 的 `handleSubmit` 开始：`ShelterForm` 校验输入 → `src/api/shelterManagement.ts` → 请求拦截器添加 token → Vite `/api` 代理 → 后端 `src/app.ts` 注册的 `src/modules/shelters/routes.ts`。

路由先执行 `requireLogin`、`requireAdmin`，再调用 `service.ts`。业务层独立校验原始输入，把 location 拆成 longitude、latitude、height 列，把 facilities 转为 JSON 文本。每次新增或更新使用一条 SQL 同时写入所有资料，避免留下半份记录；读取时还原嵌套对象和设施数组。参数使用 SQL 占位符，筛选列与排序来自固定代码。`types.ts` 说明接口资料、单位及系统字段。

前端保留原有列表与详情的异步保护 Hook：筛选、刷新、切换详情或卸载会取消过期请求，旧响应不能覆盖新结果。查询与编辑表单使用不同名称，避免重复控件编号。保存失败显示后端原因并保留输入；列表失败提供重试；删除当前页最后一条时退回上一页。
