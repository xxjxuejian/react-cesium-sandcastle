# 用户管理接口与学习说明

更新日期：2026-11-07。对应阶段 3；登录与用户管理共用后端 SQLite 的 `users` 表。

## 如何运行

1. 在后端仓库 `react-cesium-server/` 按 README 安装依赖，执行 `pnpm db:migrate`、`pnpm db:seed`，然后运行 `pnpm dev`。管理员密码使用自行初始化的值。
2. 在前端仓库 `react-cesium-sandcastle/` 的 `frontend_single` 分支运行 `pnpm dev:backend`。
3. 管理员进入“系统管理 → 用户管理”；普通用户没有管理菜单，直接调用管理接口返回 403。

`pnpm dev` 保留 Mock 演示。Mock 列表与模拟登录账号独立，新增、停用、删除和模拟重置不会改变登录账号；页面有明确提示。真实账号验收使用 `pnpm dev:backend`。

## 接口契约

全部接口要求 `Authorization: Bearer <token>`，并依次校验有效会话及管理员身份。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/system-management/users` | 查询分页列表 |
| POST | `/api/system-management/users` | 新增账号，必填初始密码 |
| PUT | `/api/system-management/users/:id` | 整体更新普通资料，不修改密码 |
| DELETE | `/api/system-management/users/:id` | 删除账号及其全部会话 |
| PUT | `/api/system-management/users/:id/password` | 重置密码并撤销全部会话 |

GET 支持 username、nickname、department、phone 的不区分英文大小写的字面子串匹配，以及 status 精确匹配。page 默认 1，pageSize 默认 10，必须为正整数且每页最多 100 条。先筛选计数再分页，按创建时间倒序、编号升序稳定排序。空列表仍返回成功及 total。

新增和编辑资料包括 username、nickname、status、gender、department、role、phone、email。username、nickname 去除首尾空格后为 1～64 个字符；用户名区分大小写且唯一。status 为 enabled/disabled，gender 为 male/female/unknown，role 为 admin/viewer。部门为最多 100 个字符的普通文本。部门、电话和邮箱可省略，省略或清空后保存为空字符串；非空电话须为 1 开头的 11 位数字，邮箱最多 254 个字符并验证基本格式。

新增额外提交 password；重置只需 `{ password }`。密码长度为 15～128 个字符，保留首尾空格。普通编辑即使携带 password 也不会修改密码。其他未知字段忽略，id、createdAt 和 password_hash 等系统字段不能由请求覆盖。

成功响应为 `{ code: 0, message, data }`。列表 data 为 `{ list, total }`；新增和编辑返回资料；删除和重置返回 true。资料返回 id、上述八个资料字段、北京时间格式的 createdAt；不返回密码、密码哈希和会话数据。数据库内部时间保存为 UTC。

失败使用真实 HTTP 状态及 `{ code, message, data: null }`：400 参数错误、401 会话失效、403 无管理权限、404 用户不存在、409 用户名冲突或最后一个管理员保护；解析和大小限制沿用全局 400/413，未预期错误为 500。

## 一次保存如何执行

前端 `src/pages/system-management/user-management/index.tsx` 打开 `UserFormModal`，表单校验后调用 `src/api/userManagement.ts`。`src/utils/request.ts` 添加 Bearer token，经 Vite 代理到后端。

后端 `src/app.ts` 注册 `src/modules/users/routes.ts`。路由读取 HTTP 输入，`service.ts` 执行参数校验与 SQL；`types.ts` 描述业务资料。这三个文件让请求流程和数据库规则能够分开阅读；当前没有额外的 controller、repository 或通用 CRUD 基类。

新增或重置先异步计算密码哈希，计算期间不持有数据库事务；哈希结束后再次检查当前管理员会话，避免已停用或降级的管理员继续写入。

更新、删除和重置在同步事务中执行。`BEGIN IMMEDIATE` 先获得写锁，在同一事务内检查最后一个启用管理员并修改数据；异常回滚。停用会删除所有会话，重置会同时修改密码及删除会话，删除账号通过外键级联删除会话。重新启用不会复活旧 token，用户必须重新登录。角色变化由每次请求查询到的当前角色决定权限。

前端修改自己的资料后重新恢复会话，及时更新昵称、角色和路由；停用、删除或重置自己的密码时，旧 token 失效并回到登录页。请求失败保留弹窗输入并显示后端原因。筛选变化和页面卸载会取消旧列表请求，防止旧响应覆盖新结果。

本阶段继续使用原有 users、sessions 表，无需增加迁移。后续阶段 4 再新增 shelters 表与避难场所接口。
